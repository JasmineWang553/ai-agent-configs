## Vault

- Location: `~/Desktop/dtc-vault`.
- `~/Desktop/dtc-vault/CLAUDE.md` is the schema and it wins. Read it before the first write of a session.
- Obsidian vault. Notes are markdown with YAML frontmatter. Links are `[[note name]]`.

## Layers

| Folder | Holds | I write? |
|---|---|---|
| `raw/` | Sources: MR JSON, exports, pasted files | Never. Immutable. |
| `system/` | Services, endpoints, topics, libraries | Only under `## Changes by me` |
| `flows/` | Why an endpoint or topic runs, services reached, result | Yes |
| `code/` | Per service: code layout, MRs, review comments | Yes |
| `projects/` | Billing projects and team work | Yes |

- `system/` is generated by `repo_map.py`. A re-run overwrites the generated sections, so my own work goes only under the trailing `## Changes by me` heading.
- Service notes live at `system/services/<service>.md`. Link them as `[[system/services/<service>|<service>]]`.

## Note format

- Frontmatter `type` is required. One of: `service`, `endpoint`, `topic`, `flow`, `code`, `mr`, `project`, `index`.
- Body in ASD-STE100 short style: bullets, short sentences, small ASCII diagrams, tables for 3 or more compared items.
- A flow note states: trigger, services reached, what is returned, end result. Kafka flows: producer, topic, consumer, end result.

## Routing a new fact

```
config / endpoint / topic / service fact  -> system/  (update the matching note)
why an endpoint runs, services reached    -> flows/
MR, review comments, code layout          -> code/<service>/
billing or project info                   -> projects/
```

- Update an existing note before creating a new one. Search first.
- `dtc-release-manifest` is excluded from `code/` and `projects/`. Its raw files still belong in `raw/`.

## Every write, in order

1. Say in two lines what the input is and where it goes. Ask if it is unclear.
2. Write or update the note.
3. Link to the source in `raw/` when the fact came from a file there.
4. Update the folder `index.md`, and the root `index.md` if a folder gained its first note of a kind.
5. Append one entry to `log.md`. Format: `## [YYYY-MM-DD] <verb> | <title>` plus bullets listing what changed. Append only.
6. Check the links resolve. A `[[target]]` must match a real file path.

## Reading

- Read the folder `index.md` first, then the notes it lists.
- Save a good answer back as a note so the next question is cheap.

## Lint on request

Check for contradictions, stale claims, orphan notes, missing links, empty sections, and any `[[link]]` with no target.

## Verbs for log entries

`ingest`, `trace`, `lint`, `reorg`, `cleanup`, `rewrite`, `revert`, `fix`, `setup`.
